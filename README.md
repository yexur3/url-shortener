# URL Shortener + Analytics API

A backend service for creating short, shareable links with click analytics — built solo as a portfolio project using Java and Spring Boot.

## Features

- **Short link generation** — converts long URLs into short, unique codes using Base62 encoding
- **Redirects** — resolves short codes back to the original URL via HTTP 302 redirect
- **Click analytics** — tracks every redirect (timestamp, IP address, referrer, user agent) alongside a fast click counter
- **Redis caching** — frequently accessed short codes are cached to avoid unnecessary database reads on the redirect path
- **Asynchronous click logging** — click tracking runs on a separate thread so it never delays the redirect response to the user

## Tech Stack

- **Backend:** Java 17, Spring Boot, Spring Data JPA
- **Database:** PostgreSQL
- **Caching:** Redis
- **Infrastructure:** Docker Compose (Postgres + Redis for local development)
- **Other:** Lombok, Bean Validation

## How It Works

1. `POST /api/urls` — submit a long URL, receive a short link back. The service saves the URL, gets an auto-generated ID from the database, encodes that ID into a short Base62 code, and stores it.
2. `GET /{shortCode}` — resolves the short code:
   - Checks Redis first for the original URL (cache hit → skips the database read)
   - Falls back to PostgreSQL on a cache miss, then populates the cache for next time
   - Returns an HTTP 302 redirect to the original URL
   - Logs the click (IP, referrer, user agent) and increments the click counter **asynchronously**, so the redirect response isn't delayed by the database write
3. `GET /api/urls/{shortCode}/analytics` — returns the total click count and a detailed list of individual click events for a given short link

## Architecture Notes

- **Base62 encoding**: short codes are generated by encoding the database-assigned numeric ID into a 62-character alphabet (0-9, a-z, A-Z), keeping codes short even for large IDs.
- **Async click logging**: click logging is implemented in a dedicated `ClickLoggingService` (separate from the main `ShortUrlService`) and marked `@Async`. This was a deliberate design choice — Spring's `@Async` only works when a method is invoked through the Spring proxy, which doesn't happen with self-invocation (a class calling its own `@Async` method directly). Moving the logic to a separate service ensures the redirect endpoint returns immediately while click data is written in a background thread.
- **Caching strategy**: only the original URL is cached (not the full analytics data). Click count and click history are always written to PostgreSQL directly — Redis is used purely to speed up the hot read path (resolving a short code to its target URL), not as a source of truth for click data.

## Running Locally

```bash
# Start PostgreSQL and Redis
docker-compose up -d

# Run the application
./mvnw spring-boot:run
```

The API will be available at `http://localhost:8080`.

## API Reference

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/urls` | Create a short URL |
| GET | `/{shortCode}` | Redirect to the original URL |
| GET | `/api/urls/{shortCode}/analytics` | Get click analytics for a short URL |
